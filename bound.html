Research note 002 · Agent control

Coding agents know how to continue.

BOUND explores a different question: when is the observed result good enough to stop refining the current objective?

View the end-to-end resultOpen BOUND on GitHub
StepContract + observed evidence ↓ deterministic policy ↓ ACCEPT · RETRY · REPLAN · ROLLBACK

The missing boundary in agent execution

Modern coding agents can plan, edit files, run tools, inspect failures, and continue working. Continuation is their default. A task can already be satisfactory—tests pass and the requested behavior works—while the agent keeps refining, spending resources, or introducing new risk.

The next question is not always “what should the agent do?” Sometimes it is “should the agent do anything else at all?”

A thin deterministic control harness

BOUND sits after a meaningful execution step and before the agent selects its next action. It does not generate code and it does not replace the agent.

01

Contract

Define observable acceptance, risk, artifacts, and budgets.

02

Execute

The agent plans, edits code, uses tools, and runs verification.

03

Observe

Collect only evidence the environment actually produced.

04

Evaluate

BOUND calculates a reproducible policy decision.

05

React

The surrounding agent changes its control flow.

ACCEPT

The result crossed the threshold. Stop refining this step.

RETRY

The approach is close. Make one focused correction.

REPLAN

The strategy is too far off. Choose a materially different approach.

ROLLBACK

A hard risk boundary was exceeded. Return to a confirmed safe state.

Evidence, not invented confidence

For observable criteria, BOUND does not require another LLM to judge the first LLM. Tests, lint, type checks, expected and unexpected artifacts, retries, tool use, runtime, and rollback availability can become explicit execution evidence. Signals that cannot be measured remain unavailable.

S = (WA × Acceptance) + (WI × Influence) - (WR × Risk) - (WC × Cost) objective: cross the configured threshold not: maximize the score forever

The control loop worked end to end

In a small todo-service experiment, an agent installed and integrated BOUND, created a contract for standards-compliant CSV export, and evaluated two real implementation attempts.

Attempt 1

Manual CSV construction

1 / 3

Required checks passed. Commas and embedded newlines were corrupted.

tests: failed score: -0.0417 threshold: 0.7500 Decision: REPLAN
→
Attempt 2

Standard-library CSV writer

3 / 3

Required checks passed. Special characters round-tripped correctly.

tests: passed score: 0.7500 threshold: 0.7500 Decision: ACCEPT

BOUND did not choose csv.DictWriter or write the replacement implementation. It returned REPLAN. The agent chose the new strategy. When the evidence later crossed the threshold, BOUND returned ACCEPT and the agent stopped refining the objective.

One prompt as the adoption layer

The integration is deliberately agent-driven. A user installs the Agent Skill or pastes one integration prompt into a coding agent. The agent inspects the real project, finds meaningful evaluation boundaries, identifies available and missing evidence, and proposes a thin integration before changing anything.

Planning and control are complementary

This is where BOUND connects to the longer-term Societas Labs research direction.

DeWorldModel

Predict and compare plausible future software states before execution.

+

BOUND

Evaluate observed execution outcomes and determine whether to accept, retry, replan, or roll back.

A future agent system could use a software world model to select a promising trajectory, execute a meaningful step, and use BOUND to decide whether the real outcome is sufficient to continue. One layer reasons about possible futures; the other governs progress using observed evidence.

Experimental status

The end-to-end result demonstrates self-integration, deterministic evaluation, and control-flow adaptation. It does not yet demonstrate that BOUND reduces tokens, calls, runtime, or regressions across workloads.

Demonstrated

Prompt-driven integration, honest evidence collection, reproducible policy output, and an agent reacting to REPLAN and ACCEPT.

Next experiment
