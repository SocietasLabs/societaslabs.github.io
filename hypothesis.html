Core hypothesis

Agents should plan software like humans do.

Humans rarely start by typing the final implementation. We first understand intent, architecture, constraints, and the shape of the solution. Software World Models asks whether AI agents can be given a similar layer of insight before execution.

View hypothesis Research note
Human engineer: understand goal inspect architecture reason about constraints plan change path then implement Current agent: edit test fail retry Hypothesis: latent planning can become the missing middle layer

Not just the next edit.

The goal is not to predict that a function needs type hints or that a file needs a logging statement. Those are surface edits. The deeper question is whether a model can learn concepts such as reliability, observability, modularity, service boundaries, and microservice architecture as directions in latent software space.

Surface level

Add type hints, add logging, add retry handling, rename variables, update tests.

Concept level

Understand reliability, service ownership, coupling, observability, and architectural intent.

Planning level

Predict the path from current software state toward a desired architecture before editing code.

A useful software world model should not only know what code can be written. It should help an agent understand what kind of system the code is becoming.

From goal to architecture

A human engineer can hear “move this toward a microservices architecture” and understand that this is not one edit. It involves boundaries, contracts, ownership, deployment shape, observability, failure modes, and gradual migration.

Latent space as an insight layer

We believe latent space may become a useful planning surface for agents: a place where software states, goals, and architectural concepts can be compared before code is changed.

The bigger goal

The long-term goal is to give AI agents a form of software insight: not consciousness, but a learned internal sense of how systems are structured, how they evolve, and what consequences a change may have before it is executed.

For coding agents

A planning layer that helps agents reason about architecture, dependencies, failure modes, and future repository states before editing code.

For language models

A way to augment LLMs with predictive structure: helping them move from fluent code generation toward deeper software understanding.

Working hypothesis

current repository state + software goal ↓ latent software state ↓ future state rollout ↓ planning signal ↓ better agent action
